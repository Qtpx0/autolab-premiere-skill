## Premiere Pro + AutoLab Tool Routing (MANDATORY)

เมื่อผู้ใช้สั่งงานเกี่ยวกับ Premiere Pro (เช็คสต็อก, ดู bin, ตัดไฮไลท์, ใส่กรอบ, export):

1. **อ่าน SKILL.md ของ `autolab-premiere-automation` (หรือสกิลประจำตัวผู้ใช้) ก่อนทำอะไรทั้งสิ้น**
2. **ห้ามใช้ premiere-pro MCP tools (`get_bin_contents`, `list_project_items`, `search_project_items`, `get_full_project_overview`) สำหรับเช็คสต็อกหรือดู bin เด็ดขาด** — ใช้ `autolab_pr_inspect` เท่านั้น (เร็วกว่า 100 เท่า, output ไม่ล้น)
3. **ห้ามอ่าน `output.txt` ที่ค้างอยู่จากเซสชันเก่า** — มันเป็นขยะ ไม่ใช่ข้อมูลปัจจุบัน
4. **เมื่อมีคำสั่งให้ตัด (เช่น 'ตัดให้เลย', 'ตัดเพิ่ม', 'ถ้ามีก็ตัดให้'):** ถ้าพบว่ามี `HIGHLIGHTS_` เก่าใน Work Bin เป้าหมาย หรือ `pr_inspect` ติดป้าย `needsRecovery: true` (มีฟุตเทจใน `ไฟล์ต้นฉบับ`) — **ห้ามนำ Sequence เก่ามาส่ง Export เด็ดขาด 100%** ต้องรัน `pr_prepare_ep` เพื่อดึงฟุตเทจออกมาและล้างของเก่าทิ้ง (เฉพาะใน Work Bin นั้น) แล้วเริ่มตัดใหม่สดๆ ตั้งแต่ Auto Highlights เสมอ!
5. **Live Step-by-Step Reporting (รายงานความคืบหน้าระหว่างทาง):** ในกระบวนการทำงานที่มีขั้นตอนยาวๆ ให้ AI พิมพ์ข้อความสั้นๆ 1 บรรทัดอัปเดตสถานะบนหน้าแชทบอกผู้ใช้ก่อนเริ่มแต่ละขั้นตอนเสมอ (เช่น ก่อนเริ่มกู้ฟุตเทจ, ก่อนเริ่มรัน Auto Highlights, ก่อนเริ่มจัดกรอบ Auto Frame, ก่อนส่ง Export AME) ห้ามปล่อยให้หน้าจอเงียบหายไปเฉยๆ!
6. **จัดการ Bin ใน Premiere Pro (สร้าง/ลบ/ย้าย/ส่องผัง):** ใช้เครื่องมือสำเร็จรูป `pr_create_bin` (สร้าง nested path อัตโนมัติ), `pr_delete_bin` (ลบแบบ force clean), `pr_move_item` (ย้ายคลิปพร้อมสร้างปลายทางออโต้), และ `pr_bin_tree` (ส่องผัง Bin & คลิป); หากต้องซ่อม State นอกเหนือจากนี้ ให้ใช้ `autolab_call_jsx` เขียน ExtendScript สั่ง Premiere Pro ตรงตามข้อ 0 ของ SKILL.md ทันที!
7. **Auto Frame & Auto Scale:** เมื่อเรียกใช้ Master Profile หรือใส่ Frame/Promo ให้ส่ง `autoFit: true` เสมอเป็นค่าเริ่มต้น เพื่อให้ระบบ Auto Scale คำนวณจัดกรอบและวัดขอบดำหน้างานจริง (เว้นแต่ผู้ใช้สั่งล็อกสเกลตายตัว ค่อยส่ง `autoFit: false`)
8. **Inspection Query Audit:** ตรวจสอบฟิลด์ `queryAudit` ในผลลัพธ์ของ `pr_inspect` เสมอ; หากเรื่องใดขึ้น `found: false` แต่มี `closestBins` ให้ถามผู้ใช้สั้นๆ 1 บรรทัดเพื่อยืนยันชื่อเรื่อง ห้ามมโนสรุปว่าไม่มีบินเด็ดขาด!
9. **Zero-Delay Disk Creation & Strict Prefix Matching:** เมื่อมีคำสั่งให้ตัดเรื่องใด ให้จับคู่โฟลเดอร์บน Disk จาก "ชื่อเรื่องหลักส่วนหน้า" (Prefix ก่อนเครื่องหมาย `-` หรือ `- -`) เท่านั้น ห้ามจับคู่กับข้อความ Note/Memo ด้านหลังเด็ดขาด (โฟลเดอร์ที่มี Note ต่อท้าย ยังคงเป็นของเรื่องหลักส่วนหน้า ห้ามแตะ ห้ามเคลม และห้าม Rename เด็ดขาด); หากบน Disk ยังไม่มีโฟลเดอร์ที่ขึ้นต้นด้วยชื่อเรื่องนั้นตรงๆ ให้สร้างโฟลเดอร์ใหม่ชื่อคลีนของเรื่องนั้นทันที (หรือปล่อยให้ `pr_export_ame` สร้างอัตโนมัติ) แล้วลุยต่อจนจบ ห้ามหยุดถามขออนุญาตสร้างโฟลเดอร์ และห้ามแย่ง/Rename โฟลเดอร์เรื่องอื่นมาใช้เด็ดขาด! (การ Rename ป้ายสถานะ อนุญาตเฉพาะโฟลเดอร์ของเรื่องตัวเองที่มี `- - จะหมด` ต่อท้ายเท่านั้น)
10. **Central Raw Pool ➔ Work Bin Routing (คลังฟุตดิบรวม ➔ Bin ทำงานแยกเพจ/ตอน — กฎเหล็กห้ามสลับ Bin เด็ดขาด):**
    - **คลังฟุตดิบกลาง (`Raw Pool`):** ฟุตเทจดิบของเรื่องจะถูกโหลดมาพักรวมไว้ที่ `<ชื่อเรื่อง>/รอ` เสมอ เพื่อรอให้หยิบไปตัด
    - **Work Bin ประจำเพจ/ตอน:** เมื่อตัดลงเพจย่อย (เช่น `<ชื่อเรื่อง> - <ชื่อเพจ/คนตัด>`) หรือแบ่งตอน (`ep<เลขตอน>`) หากยังไม่มี Work Bin ให้ใช้ `pr_create_bin` สร้างทันที
    - **กลไกการดึงไฟล์ (Pull Protocol):** ตรวจสอบใน Work Bin เป้าหมายก่อนว่ามีฟุตเทจค้างอยู่หรือไม่ ถ้าว่างเปล่าให้ใช้ `pr_move_item` ดึงฟุตเทจ 1 คลิปจากคลังกลาง `<ชื่อเรื่อง>/รอ` ย้ายเข้ามาใน Work Bin นั้น; หากในคลังกลางไม่มีคลิปเหลือเลย ➔ **STOP ทันที 100%** และรายงานผู้ใช้สั้นๆ 1 บรรทัด ห้ามเดาและห้ามสลับไปดึงไฟล์ของเรื่องอื่นเด็ดขาด!
    - **การลบ `HIGHLIGHTS_` (Strict Isolation):** ลบ `HIGHLIGHTS_` ได้ **เฉพาะที่อยู่ใต้ Work Bin ของตัวเองเท่านั้น** ห้ามแตะต้อง, ห้ามดึงของ และห้ามลบ `HIGHLIGHTS_` ของคลังกลางหรือของเพจอื่นเด็ดขาด 100%!
11. **Category-Aware Batch Partitioning (Auto Highlights Speed Isolation):** เนื่องจากค่า Speed Assist ใน Auto Highlights เป็นค่า Engine ระดับ Batch รวม (`ah_configure`) หากผู้ใช้สั่งตัดหลายเรื่องพร้อมกันที่มีทั้ง **งานหนัง/ซีรีส์ (เปิด Speed 1.15×)** และ **งานรายการ (ปิด Speed)** ห้ามเทรวมคิว AH เดียวกันเด็ดขาด (เพราะจะทำให้สปีดเสียงตีกัน)! ให้ AI ทำการแบ่งกลุ่มรัน Auto Highlights แยกตามสูตรสปีดอัตโนมัติ (เช่น รันกลุ่มหนังที่เปิด Speed ก่อน ➔ สลับ Preset ปิด Speed ➔ แล้วรันกลุ่มรายการต่อ) โดยทำต่อเนื่องจนจบงานโดยไม่ต้องหยุดถาม!
12. **Zero-Delay AME Auto-Render:** คำสั่ง `pr_export_ame` ใน v1.8.2 เปิดใช้งาน `startQueue: true` เป็นค่าเริ่มต้น โดยจะเรียกใช้ `app.encoder.startBatch()` ใน ExtendScript เริ่มเรนเดอร์คิวทันทีใน 0ms ปลอดภัย 100% ไม่สะดุด ไม่หยุดคิว และไม่ต้องคอยกด Start Queue เองหรือรอตัวนับถอยหลัง 2 นาที
13. **Smart Low-Stock Auto-Inspection:** เมื่อเรียก `pr_inspect` โดยระบุ `diskRoot` พร้อม `categoryBin` โดยไม่ใส่ `queries` ระบบจะคัดกรองเฉพาะเรื่องที่สต็อกใกล้หมด (`lowStockShows` <= 15 คลิป) นำไปสแกนใน Premiere Pro อัตโนมัติใน `< 0.2s` และจะไม่นำเรื่องที่มีสต็อกตุนเยอะ (> 20 คลิป) เข้ามาใน `readyToCut` เด็ดขาด
14. **Standard Stock Dashboard Table Protocol (มาตรฐานตารางสรุปผลสต็อก):**
    - **ห้ามรายงานผลการเช็คสต็อกเป็น Bulleted List หรือข้อความย่อหน้าซ้อนกันเด็ดขาด** (อ่านยากและสร้างความสับสน)
    - **ต้องแสดงผลเป็นตาราง Markdown Table สรุปแบบ Dashboard เสมอ** แบ่งคอลัมน์มาตรฐาน: `ลำดับ` | `เรื่อง` | `สต็อกบน Disk` | `ตอนที่เหลือบน Disk` | `สถานะใน Premiere Pro` | `Action ที่ต้องทำ`
    - **จัดเรียงตามความเร่งด่วน:** เรียงจากเรื่องที่สต็อกเหลือน้อยสุด/หมดขึ้นก่อน (🔴 สต็อกวิกฤต 0–2 คลิป ➔ 🟡 สต็อกปานกลาง ➔ 🟢 มีฟุตเทจดิบพร้อมตัดทันที ➔ ⚪ สต็อกปลอดภัย)
    - **สรุป Action สั้นๆ ใต้ตาราง 2 บรรทัด:** แยกชัดเจนว่าเรื่องไหนมีฟุตเทจพร้อมลุยตัดต่อได้ทันที และเรื่องไหนต้องโหลดฟุตเทจใหม่เข้ามาเติม
    - **Clean Thai Output 100%:** ห้ามมีข้อความคิดในใจหรือประโยคภาษาอังกฤษหลุดปนออกมานอกตารางเด็ดขาด
